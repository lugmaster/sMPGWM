# Cleanup audit — 2026-11-12

This source audit originally proposed the cleanup below. The user subsequently authorized implementation; see the implementation status below. The user has closed the other verification work for the measurement pass and deferred another remote Steam test until after upcoming features. No recommendation below depends on claiming Steam coverage.

## Implementation status

The authorized cleanup adds the production 60 FPS cap, removes the category-parser forwarding wrapper and unused game-state event, narrows the three lifecycle methods to private, and replaces implicit ship-loadout creation with explicit initialization and safe partial-construction cleanup. The obsolete FileLoader navigation import was already absent when implementation started.

The retained responsibilities below are unchanged. In particular, item stat precompilation, failed-preparation reset/retry, session/protocol guards, runtime rebinding, and new/restored-state distinctions remain. No topology or snapshot encoding optimization is included. The archived performance results describe the pre-cleanup baseline; performance remeasurement remains deferred.

Validation: `dotnet test sMPGWM.sln --no-restore --results-directory artifacts/cleanup-validation --logger "trx;LogFileName=cleanup.trx"` passed on 2026-11-12. The runner reported 303 passes: 302 managed cases plus the Godot wrapper. The wrapper separately reported 230 in-engine passes, including three new ship regressions for explicit loadout configuration, failure before loadout construction, and failure after construction followed by a successful retry. The explicit performance/process benchmarks were not run. Local TRX and attached engine results are under the Git-ignored `artifacts/cleanup-validation` directory.

Rider safe-delete accepted the forwarding method and event removals without conflicts after callers were redirected/removed. Independent review found no loadout-cleanup blocker. New test support has unique traceability IDs and no production test hooks were added. `git diff --check` passed. The build still reports the existing `UiIcon.Size` member-hiding and `AbilityArchitectureTests` NUnit2009 warnings. Rendered frame-cap validation and performance comparisons remain deferred; no speedup or resolution of the measured GC spikes is claimed.

## Scope and validation notes

The audit covers the named lifecycle owners, registry/loader ownership, fresh/restored installation, local binding and join-state boundaries. Source searches include production C# and Godot scene bindings; proposed access narrowing assumes no separately distributed binary mod consumer. It does not claim a universal external API usage search.

No tests were added or run solely for this read-only audit. Existing regression names identify checks to run when the proposals are implemented. Performance evidence is supplied by the accompanying measurement work; this audit makes no unsupported speedup claim. No second production activation mechanism was found: normal startup still flows through `SessionInitialization.Synchronize` → `SessionCoordinator.CompleteLoading` → `GameFlowManager.CompleteLoading` → local presentation activation. The public mutators above are unnecessary exposure of that path, not evidence that a second caller currently uses it.
